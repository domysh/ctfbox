# The public site

`ctfbox.domy.sh` is not a snapshot anybody edits by hand. It is the real
scoreboard frontend, built from `gameserver/frontend/`, served against API
fixtures generated by [`build.py`](build.py), with the configuration editor
overlaid at `/editor`. `.github/workflows/static.yml` rebuilds and redeploys it
on every push to `main`, so the demo always shows the frontend as it is now —
the organizers' control room included.

Build it locally:

```bash
./demo/build.py             # builds the frontend too, into ./_site
./demo/build.py --skip-build  # reuse gameserver/frontend/dist
python3 -m http.server 8099 --directory _site
```

## What the fixtures contain

`build.py` plays a small deterministic game: eight teams with different skill
and different luck, three services (one of them worth double), seventy rounds of
history, scored with the same formula as the game server. Deterministic on
purpose — a rebuild must not reshuffle the scoreboard for no reason.

From that it writes every endpoint the frontend asks for: the public scoreboard,
chart, team history and announcements, and the whole `/api/admin` surface —
overview, nodes and workers, teams, services, checker jobs, attack graph,
traffic, submissions with their statistics, capture status, and a small real
`.pcap` so the download button hands back something a capture tool can open.

## The admin panel in the demo

`/api/admin/whoami` answers `{"admin": true, "demo": true}`. The `demo` flag is
never set by the real game server: it makes the panel render a "read-only demo"
banner and refuse anything that is not a GET, so a static host never has to
answer a request that would change something.
